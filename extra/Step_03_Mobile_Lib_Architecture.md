# `mobile/lib/` — Complete Source Code Architecture Guide

The **`mobile/lib/`** directory is the heart of the CSE JnU EduPortal mobile application. Built using Flutter and structured according to **Feature-Driven Clean Architecture**, it contains all the client-side Dart code.

It is strictly organized into four layers plus the application entry point:
1. **Entry Point & Platform Config** (`main.dart`, `firebase_options.dart`)
2. **App Shell** (`app/`) — Root widget, declarative routing with RBAC guards, and theming.
3. **Core Infrastructure** (`core/`) — Shared non-feature utilities (DI, network, secure storage, errors).
4. **Shared UI Components** (`shared/`) — Reusable Design System widgets (buttons, cards, inputs, states).
5. **Feature Modules** (`features/`) — 9 isolated domain feature packages (`auth`, `dashboard`, `attendance`, etc.).

## 1. 🚀 Entry Point & Platform Config

### `main.dart`
* **Purpose**: The bootstrapper of the mobile application.
* **Responsibilities**:
  1. Ensures Flutter widget bindings are initialized (`WidgetsFlutterBinding.ensureInitialized()`).
  2. Initializes Firebase via `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`.
  3. Registers all dependencies into the `GetIt` service locator container via `initializeDependencies()`.
  4. Creates the global `ValueNotifier<ThemeMode>` (persisted in local storage).
  5. Boots the root widget: `runApp(CSEEduPortalApp(...))`.

### `firebase_options.dart`
* **Purpose**: Auto-generated by FlutterFire CLI. Contains Google Cloud / Firebase API keys, Project IDs, Storage Buckets, and App IDs tailored per target platform (Android, iOS, macOS, Web).

## 2. 🏛️ `app/` (Application Shell)

Wires together app-wide systems: root widget, declarative routing, and theming.

* **`app.dart`**:
  * Hosts `CSEEduPortalApp`, which builds Flutter's `MaterialApp.router`.
  * Integrates the light and dark `ThemeData`.
  * Injects a global gesture handler: tapping anywhere outside an active text input dismisses the software keyboard (`FocusManager.instance.primaryFocus?.unfocus()`).
* **`router/`**:
  * **`route_names.dart`**: Constant definitions for all URL routes (`/`, `/login`, `/dashboard/student`, `/dashboard/teacher`, `/attendance`, etc.).
  * **`app_router.dart`**: Built on `GoRouter`. Contains real-time **Role-Based Access Control (RBAC) guards**:
    * Redirects unauthenticated requests to `/login`.
    * Prevents students from opening `/dashboard/teacher` or `/dashboard/admin`.
    * Automatically sends logged-in users straight to their role-specific dashboard.
* **`theme/`**:
  * **`app_colors.dart`**: Primary palette tokens (**Emerald Scholar** `#006948`, Obsidian Terminal `#18181B`, surfaces, borders).
  * **`app_typography.dart`**: Configures Google Fonts (**Plus Jakarta Sans** for headings/body, **JetBrains Mono** for codes/terminals).
  * **`app_theme.dart`**: Material 3 light and dark theme configurations.
  * **`role_colors.dart`**: Visual badges and color identities for each role (Student, CR, Teacher, Admin).
  * **`theme_controller.dart`**: Toggles light/dark/system theme modes and persists preferences.

## 3. ⚙️ `core/` (Cross-Cutting Infrastructure)

Contains foundational utilities completely decoupled from specific UI features.

* **`di/` (`injection_container.dart`)**:
  * Uses `GetIt` (`sl` = Service Locator).
  * Registers singletons and factories for: DataSources, Repositories, Use Cases, Controllers, and Storage.
* **`storage/`**:
  * **`secure_storage_service.dart`**: Uses `FlutterSecureStorage` (iOS Keychain / Android Keystore) to store auth credentials and secrets safely.
  * **`local_storage_service.dart`**: Uses `SharedPreferences` for non-sensitive cached items (theme mode, offline routine cache).
* **`error/`**:
  * **`failures.dart`**: Pure domain failure representations (`ServerFailure`, `AuthFailure`, `NetworkFailure`, `ValidationFailure`).
  * **`exceptions.dart`**: Data-layer exceptions (`ServerException`, `UnauthorizedException`).
  * **`error_handler.dart`**: Translates raw exceptions (including `FirebaseException`) into typed user-facing failures.
* **`constants/`**:
  * **`app_constants.dart`**: App name, timeout durations, pagination defaults.
  * **`role_constants.dart`**: Enums for `UserRole` (`student`, `cr`, `teacher`, `admin`).
* **`logging/` (`app_logger.dart`)**: Structured log formatting with log levels (debug, info, warning, error).
* **`utils/`**:
  * **`validators.dart`**: Email, password, student roll, and phone validation regexes.
  * **`formatters.dart`**: Date/time formatting, currency, and academic semester labels.
  * **`context_extensions.dart`**: BuildContext helpers (`context.theme`, `context.colors`, `context.showSnackBar`).
*(Note: Legacy REST `network/` stubs and `api_endpoints.dart` were removed following the complete migration to native Firebase SDK operations.)*

## 4. 🎨 `shared/` (Design System UI Component Library)

Shared, reusable UI components adhering to the **Emerald Scholar** design system.

* **`presentation/foundation_preview_screen.dart`**: Interactive living style guide / component preview showcase displaying buttons, typography, colors, and states.
* **`widgets/buttons/`**:
  * `app_primary_button.dart`: Main emerald action button with loading spinners and disabled states.
  * `app_secondary_button.dart`: Outline style button for secondary actions.
  * `app_text_button.dart`: Borderless text button.
* **`widgets/cards/`**:
  * `app_card.dart`: Container with rounded corners (`rounded-2xl`) and subtle elevation/shadows.
  * `role_badge_chip.dart`: Visual tag identifying user role (e.g., green for Student, purple for CR, blue for Teacher, red for Admin).
  * `assigned_course_card.dart`: Course card displaying code, title, and credit hours.
* **`widgets/inputs/`**:
  * `app_text_field.dart`: Styled input with validation support, label text, and password visibility toggling.
* **`widgets/states/`**:
  * `app_loading_view.dart`: Centered circular/pulse indicator.
  * `app_empty_state_view.dart`: Friendly illustration and message when no data exists.
  * `app_error_state_view.dart`: Error message display with a retry button.
* **`widgets/dialogs/`**:
  * `app_dialog.dart` & `app_confirmation_dialog.dart`: Reusable modal popups for destructive actions (e.g., confirming sign-out or session termination).
* **`widgets/theme/`**:
  * `theme_toggle_button.dart`: Quick toggle between light and dark modes.

## 5. 🧩 `features/` (Clean Architecture Domain Modules)

Every feature is encapsulated inside its own folder under `mobile/lib/features/` and organized into three strict sub-layers:

```text
features/<feature_name>/
├── data/
│   ├── datasources/       # Direct calls to Cloud Firestore / Firebase Services
│   ├── models/            # DTOs that serialize JSON <-> Dart
│   └── repositories/      # Concrete repository implementations
├── domain/
│   ├── entities/          # Pure Dart models (e.g., User, AttendanceSession)
│   ├── repositories/      # Abstract interfaces defining what data operations exist
│   └── usecases/          # Business logic rules (e.g., LoginUseCase, SubmitAttendance)
└── presentation/
    ├── controllers/       # State controllers / Notifiers (manage UI state)
    ├── screens/           # Full screen widgets (e.g., StudentAttendanceScreen)
    └── widgets/           # Sub-widgets private to this feature
```

## 🔄 Lifecycle: How Code in `lib/` Executes

When a user taps **"Submit Attendance Code"** on the screen, here is the exact call sequence across `lib/`:

```text
1. [presentation/screens]
   User enters "492018" and presses Submit.
   Screen calls: controller.submitAttendance("492018")
        │
        ▼
2. [presentation/controllers]
   Controller sets state = AttendanceLoading().
   Controller calls: submitAttendanceUseCase(code: "492018")
        │
        ▼
3. [domain/usecases]
   UseCase executes business rule:
   Validates code format -> calls: repository.submitAttendance(code)
        │
        ▼
4. [data/repositories]
   RepositoryImpl receives request:
   Calls: remoteDataSource.postAttendance(code)
        │
        ▼
5. [core/network or Firestore SDK]
   Network interceptor adds Bearer token -> Dispatches payload to server.
        │
        ▼
6. [data/models]
   Server returns JSON -> Model parses into Entity.
        │
        ▼
7. [presentation/controllers]
   Controller receives Entity -> updates state = AttendanceSuccess().
   Screen reactively re-renders glowing success checkmark!
```
